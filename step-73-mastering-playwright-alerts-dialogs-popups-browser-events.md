## 2. What Is a Browser Dialog?

A browser dialog is a browser-level UI component generated by
JavaScript.

Common dialog types are:

-   `alert`
-   `confirm`
-   `prompt`
-   `beforeunload`

Example:

``` javascript
alert('Welcome!');
```

The browser displays a dialog containing:

``` text
Welcome!
     [ OK ]
```

------------------------------------------------------------------------

## 3. Types of JavaScript Dialogs

### Alert

``` javascript
alert('Message');
```

### Confirm

``` javascript
confirm('Are you sure?');
```

Buttons usually include:

``` text

```

### Prompt

``` javascript
prompt('Enter your name');
```

The user can enter a value.

Real applications may use dialogs for:

-   Delete confirmations

-   Warning messages
-   Unsaved changes

-   Destructive actions
-   Browser-level navigation warnings

Confirm Dialog

## 7. Handling an Alert

Example:

``` typescript
page.on('dialog', async dialog => {
    console.log(dialog.message());

    await dialog.accept();
});
```

Then trigger the alert:

``` typescript
await page.getByRole('button', {
    name: 'Show Alert'
}).click();
```

------------------------------------------------------------------------

## 8. Complete Alert Example

``` typescript
import { test, expect } from '@playwright/test';

test('handle alert dialog', async ({ page }) => {

    await page.goto('/alerts');

    page.on('dialog', async dialog => {

        console.log(
            'Dialog type:',
            dialog.type()
        );

        console.log(
            'Dialog message:',
            dialog.message()
        );

        await dialog.accept();
    });

    await page.getByRole('button', {
        name: 'Show Alert'
    }).click();

});
```

## 9. Handling Confirm Dialog

A confirm dialog asks the user to accept or reject an action.

``` typescript
page.on('dialog', async dialog => {

    console.log(dialog.message());

    await dialog.accept();
});
```

To cancel:

``` typescript
page.on('dialog', async dialog => {

    await dialog.dismiss();
});
```

------------------------------------------------------------------------

## 10. Accepting a Confirm Dialog

``` typescript
test('accept confirmation', async ({ page }) => {

    await page.goto('/delete');

    page.on('dialog', async dialog => {

        expect(dialog.type()).toBe('confirm');

        await dialog.accept();
    });

    await page.getByRole('button', {
        name: 'Delete'
    }).click();

});
```

## 17. Dialog Handling Based on Type

You can implement logic based on dialog type:

``` typescript
page.on('dialog', async dialog => {

    switch (dialog.type()) {

        case 'alert':
            await dialog.accept();
            break;

        case 'confirm':
            await dialog.accept();
            break;

        case 'prompt':
            await dialog.accept('Sandeep');
            break;

        default:
            await dialog.dismiss();
    }
});
```

------------------------------------------------------------------------

## 18. Dialog Handling Based on Message

Sometimes the same application has multiple dialogs.

Example:

``` typescript
page.on('dialog', async dialog => {

    if (dialog.message()
        .includes('Delete')) {

        await dialog.accept();

    } else {

        await dialog.dismiss();
    }
});
```

This is useful for conditional dialog behavior.

------------------------------------------------------------------------

## 19. Important Concept --- Dialogs Must Be Handled

When a dialog appears, the page may become blocked until the dialog is
handled.

Therefore, this pattern is dangerous:

``` typescript
await page.getByRole('button', {
    name: 'Delete'
}).click();

page.on('dialog', async dialog => {
    await dialog.accept();
});
```

The dialog listener should generally be registered before the action
that triggers the dialog.

Correct:

``` typescript
page.on('dialog', async dialog => {
    await dialog.accept();
});

await page.getByRole('button', {
    name: 'Delete'
}).click();
```

------------------------------------------------------------------------

## 20. One-Time Dialog Handling

If you want to handle only one expected dialog, use:

``` typescript
page.once('dialog', async dialog => {
    await dialog.accept();
});
```

Example:

``` typescript
page.once('dialog', async dialog => {
    expect(dialog.message())
        .toBe('Operation successful');

    await dialog.accept();
});

await page.getByText('Submit').click();
```

------------------------------------------------------------------------

## 21. `page.on()` vs `page.once()`

### `page.on()`

Handles every matching event:

``` typescript
page.on('dialog', handler);
```

### `page.once()`

Handles only the next matching event:

``` typescript
page.once('dialog', handler);
```

Use `once()` when the test expects exactly one dialog.

------------------------------------------------------------------------

## 22. Removing Dialog Listeners

If you register a persistent handler:

``` typescript
const handler = async (dialog) => {
    await dialog.accept();
};

page.on('dialog', handler);
```

You can later remove it:

``` typescript
page.off('dialog', handler);
```

This is useful in complex framework-level event management.

------------------------------------------------------------------------

## 23. Global Dialog Handler

Some frameworks need a default dialog policy.

Example:

``` typescript
page.on('dialog', async dialog => {

    console.log(
        `[Dialog] ${dialog.type()}`
    );

    console.log(
        `[Message] ${dialog.message()}`
    );

    await dialog.accept();
});
```

This can prevent unexpected dialogs from blocking tests.

However, global handlers should be designed carefully.

------------------------------------------------------------------------

## 24. Why Global Dialog Handlers Can Be Dangerous

Suppose a test expects:

``` text
Delete confirmation
```

but a global handler automatically accepts every dialog.

The test could accidentally delete data.

Therefore, enterprise frameworks should use explicit policies.

------------------------------------------------------------------------

## 25. Recommended Enterprise Dialog Strategy

Use:

``` text
Expected Dialog
       ↓
Register Handler
       ↓
Validate Type
       ↓
Validate Message
       ↓
Accept/Dismiss
       ↓
Continue Test
```

Example:

``` typescript
page.once('dialog', async dialog => {

    expect(dialog.type())
        .toBe('confirm');

    expect(dialog.message())
        .toContain('Delete');

    await dialog.accept();
});
```

------------------------------------------------------------------------

## 26. Handling `beforeunload`

Some applications warn users about unsaved changes.

Example:

``` typescript
page.on('dialog', async dialog => {

    if (dialog.type() === 'beforeunload') {
        await dialog.accept();
    }
});
```

Use this only when your application actually generates the event.

## 38. Event-Driven Automation

Playwright is heavily event-driven.

The general pattern is:

``` text
Register Listener
       ↓
Perform Action
       ↓
Browser Event Occurs
       ↓
Playwright Captures Event
       ↓
Await Event Result
       ↓
Validate / Process Event
```

This pattern will appear repeatedly throughout the Bootcamp.

------------------------------------------------------------------------

## 39. Dialog + Action Pattern

Recommended:

``` typescript
const dialogPromise =
    new Promise<void>(resolve => {

        page.once('dialog', async dialog => {

            expect(dialog.message())
                .toContain('Delete');

            await dialog.accept();

            resolve();
        });
    });

await page.getByText('Delete').click();

await dialogPromise;
```

For most tests, however, `page.once('dialog', ...)` directly before the
action is simpler.

------------------------------------------------------------------------

## 40. Common Mistake --- Registering Handler Too Late

Incorrect:

``` typescript
await page.getByText('Delete').click();

page.once('dialog', async dialog => {
    await dialog.accept();
});
```

Correct:

``` typescript
page.once('dialog', async dialog => {
    await dialog.accept();
});

await page.getByText('Delete').click();
```

------------------------------------------------------------------------

## 41. Common Mistake --- Always Accepting Every Dialog

Avoid blindly doing:

``` typescript
page.on('dialog', async dialog => {
    await dialog.accept();
});
```

for every test.

This may hide important behavior.

Instead:

``` typescript
page.once('dialog', async dialog => {

    expect(dialog.message())
        .toContain('Delete');

    await dialog.accept();
});
```

------------------------------------------------------------------------

## 42. Common Mistake --- Using `waitForTimeout()`

Avoid:

``` typescript
await page.waitForTimeout(3000);
```

before handling a dialog.

Dialogs are event-driven.

Use:

``` typescript
page.once('dialog', async dialog => {
    await dialog.accept();
});
```

before the action.

------------------------------------------------------------------------

## 43. Common Mistake --- Not Validating Dialog Message

Weak:

``` typescript
page.once('dialog', async dialog => {
    await dialog.accept();
});
```

Better:

``` typescript
page.once('dialog', async dialog => {

    expect(dialog.message())
        .toContain('Are you sure');

    await dialog.accept();
});
```

This ensures that the expected dialog actually appeared.

------------------------------------------------------------------------

## 44. Enterprise Dialog Utility

You can create:

``` typescript
import { Page } from '@playwright/test';

export async function
acceptDialog(
    page: Page,
    expectedMessage?: string
) {
    page.once('dialog', async dialog => {

        if (expectedMessage) {
            if (!dialog.message()
                .includes(expectedMessage)) {

                throw new Error(
                    `Unexpected dialog: ${dialog.message()}`
                );
            }
        }

        await dialog.accept();
    });
}
```

Then:

``` typescript
await acceptDialog(
    page,
    'Are you sure'
);

await page.getByText('Delete').click();
```

------------------------------------------------------------------------

## 45. Enterprise Dialog Utility --- Dismiss

``` typescript
export async function
dismissDialog(
    page: Page,
    expectedMessage?: string
) {

    page.once('dialog', async dialog => {

        if (
            expectedMessage &&
            !dialog.message()
                .includes(expectedMessage)
        ) {
            throw new Error(
                `Unexpected dialog: ${dialog.message()}`
            );
        }

        await dialog.dismiss();
    });
}
```

## 49. Key Takeaways

The most important pattern is:

``` typescript
page.once('dialog', async dialog => {

    console.log(dialog.type());
    console.log(dialog.message());

    await dialog.accept();
});

await page.getByRole('button', {
    name: 'Delete'
}).click();
```

For prompt dialogs:

``` typescript
page.once('dialog', async dialog => {
    await dialog.accept('Sandeep');
});
```

For cancellation:

``` typescript
page.once('dialog', async dialog => {
    await dialog.dismiss();
});
```

For browser-level diagnostics:

``` typescript
page.on('console', ...);
page.on('pageerror', ...);
page.on('request', ...);
page.on('response', ...);
page.on('requestfailed', ...);
```

The core principle is:

> **Register the event listener before performing the action that
> triggers the event.**
